try {
  botaoBuscar.disabled = true;
  botaoBuscar.innerText = 'Buscando...';
  mensagem.innerText = 'Consultando a API ViaCEP...';

  const resposta = await fetch(`https://viacep.com.br/ws/${cep}/json/`);
  if (!resposta.ok) {
    throw new Error('Não foi possível consultar o serviço.');
  }
  const endereco = await resposta.json();
  if (endereco.erro) {
    mensagem.innerText = 'CEP não encontrado.';
    return;
  }

- Desabilito o botão e mudo o texto pra evitar requisição
  duplicada enquanto espera.
- fetch faz a request, await espera a resposta chegar.
- O ViaCEP tem a convenção: quando não acha o CEP, retorna
  {"erro": true} com status 200. Então tem 2 verificações:
  !resposta.ok (problema de rede/serviço) e endereco.erro
  (CEP inexistente). São coisas diferentes e eu trato as duas.

const climaApiKey = '8a60b2de14f7a17c7a11706b2cfcd87c';

async function buscarClima(cidade, uf) {
  const apiUrl =
    `https://api.openweathermap.org/data/2.5/weather?q=
     ${encodeURIComponent(cidade)},BR&appid=${climaApiKey}
     &units=metric&lang=pt_br`;

  const resposta = await fetch(apiUrl);
  const json = await resposta.json();

  if (json.cod === 200) {
    wfLocation.innerText = `${json.name}, ${uf || json.sys.country}`;
    wfTempNow.innerHTML = `${Math.round(json.main.temp)}&deg;C`;
    wfDescription.innerText = json.weather[0].description;
    wfTempIcon.src =
      `https://openweathermap.org/img/wn/${json.weather[0].icon}@2x.png`;
    wfTempMax.innerHTML = `${Math.round(json.main.temp_max)}&deg;C`;
    wfTempMin.innerHTML = `${Math.round(json.main.temp_min)}&deg;C`;
    wfHumidity.innerText = `${json.main.humidity}%`;
    wfWind.innerText = `${json.wind.speed.toFixed(1)} km/h`;

- lang=pt_br faz a descrição vir em português.
- units=metric pra temperatura em Celsius (senão vem Kelvin).
- encodeURIComponent(cidade): o nome da cidade pode ter
  espaço/acento (cidade brasileira tem muito isso), e isso
  quebraria a URL.
- json.cod === 200 é o padrão HTTP de sucesso.
- json.weather[0] é um array, sempre pego o primeiro (é o atual).
- .toFixed(1) deixa a velocidade do vento com 1 casa.

- icone é tipo "04d" (04 = condição, d = dia). d de "day", n de
  "night".
- Primeiro removo TODAS as classes de vídeo. Se eu não fizesse,
  numa segunda busca podia acumular e mostrar 2 vídeos juntos.
- Lógica por condição:
  01 -> céu limpo
  02 -> poucas nuvens
  03/04 -> nublado
  09/10/11 -> chuva, pancadas e tempestade
- Juntei os códigos 09 (pancadas), 10 (chuva) e 11 (tempestade)

  chuva.
- Uso startsWith pra variação dia/noite (03d/03n) e includes pra
  descrição. Acho mais seguro que bancar só no código, porque a
  API às vezes devolve a descrição em inglês dependendo da config.

O CARTÃO DE FICAR EM CASA / ESPORTE
===================================
- Depois que o script.js aplica a classe do clima, entra o
  condicao.js pra escolher o cartão:
    - se a classe for de chuva/tempestade (video-chuva ou
      video-pancadas) -> mostra "Tempo bom para ficar em casa"
    - qualquer outra classe (nublado, poucas nuvens, céu limpo) ->
      mostra "Tempo bom para praticar um esporte"
- Ele usa um MutationObserver pra "ficar de olho" na classe do
  card do clima e reagir quando ela muda.
- Deixei separado de propósito: o script.js decide O CLIMA, o
  condicao.js decide O CARTÃO. Cada um no seu arquivo.
